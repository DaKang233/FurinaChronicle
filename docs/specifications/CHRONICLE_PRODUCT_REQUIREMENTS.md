# Chronicle 多时间线产品规范

状态：Accepted target

本文件规定 Chronicle 最终面向用户的时间线种类、默认事件、颗粒度和展示模式，属于“本地优先的原神个人历史档案工具”的综合展示需求，不定义全部领域能力。

遵循领域自治、数据优先、开放导出、Chronicle 派生。共享 Identity、Time、Provenance、Completeness 由各自基础规范约束；领域持久化和导出由所属领域定义。EntryId、Profile、投影序列与分页字段属于 [Chronicle Timeline v1 草案](CHRONICLE_TIMELINE_V1.md)，在 Chronicle 工作包实施前冻结，不要求整个 8B.0 冻结。

## 1. 总体原则

1. 时间线展示重要历程节点，不等于展示全部规范化记录。
2. 事实是否保存、是否进入 Chronicle 投影、是否在某个时间线 Profile 中默认显示，是三个不同问题。
3. 调整颗粒度和筛选条件不得新增、覆盖或删除底层事实。
4. 每个节点必须保留账号归属、来源和时间精度；未知和不完整不得伪装成精确事实。
5. 游戏历程与导入、刷新、删除、撤销等档案操作历史继续分离。
6. 各领域先独立保存、查询、查看历史和导出，再选择哪些事实参与 Chronicle；Contributor 不是领域成立的必要条件。
7. 没有进入 Chronicle 的数据仍按领域策略长期保存并开放导出；背包、流水和高频状态观察可以主要服务领域查询与分析。

## 2. 展示模式

```text
Axis
    图表或时间轴形式

Text
    文本列表；Windows 宽屏可以使用表格，窄屏和 Android 使用列表
```

“双模式”表示同时支持 `Axis` 和 `Text`。主时间线默认使用 `Axis`，用户选择的模式可以作为可移植偏好保存。以后新增且未明确声明为双模式的时间线默认只支持 `Text`。

图标、头像和横幅仍是按需加载的可清理缓存；加载失败不得使文字节点消失。

## 3. 主时间线

主时间线为 Chronicle 默认首页，只展示以下重要节点。

### 3.1 五星物品

- 每次五星角色或武器抽取都生成节点；
- 节点至少显示物品、抽取时间、账号、卡池和来源；
- 可以额外显示距离同一账号、同一共享保底卡池组中上一个五星的抽数；
- 该抽数采用“上一个五星之后到当前五星为止，包含当前五星”的口径；
- 本地记录不足以确认完整区间时显示“未知”或“不完整”，不得给出虚假保底数；
- 角色活动祈愿 1/2 继续按共享保底组计算，其他不共享保底的卡池分别计算。

### 3.2 四星角色里程碑

- 默认显示该四星角色的第一次获取；
- 默认显示第七次获取，即达到满命的节点；
- 只有本地记录足以确认获取序号时才使用“首次”和“第七次”措辞；
- 历史不完整时使用“本地首次记录”等明确措辞，不推断缺失历史。

五星角色的每次抽取已经由五星物品规则进入主时间线，可以在节点上额外标记首次获取或满命里程碑，但不得生成内容完全相同的重复节点。

### 3.3 挑战完成

主时间线为每个账号、模式和期次最多显示一个“完成该期挑战”节点：

- 深境螺旋；
- 幻想真境剧诗；
- 幽境危战。

中间进度和完成后的成绩变化只进入挑战时间线，不重复污染主时间线。

### 3.4 重要成就

- 只有被版本化元数据标记为重要的成就进入主时间线；
- 重要成就通常包括标志魔神任务完成的成就；
- 成就重要性是元数据分类，不使用本地化名称作为稳定身份；
- 具体分类目录在成就领域实施前另行版本化，不在 Phase 8B 静默硬编码。

## 4. 角色时间线

角色时间线为双模式。

### 4.1 默认颗粒度

- 每个角色的第一次获取；
- 每个角色的第七次获取，即达到满命；
- 没有足够历史时明确显示为本地可确认的首次或里程碑。

### 4.2 提高颗粒度

用户可以选择显示角色的每一次获取事件。由抽卡记录推导的节点必须显示来源提示：

> 来源于本地抽卡记录，不包括活动赠送、自选、邮件、商店或其他非抽卡途径。

提高颗粒度不改变抽卡记录，也不把抽卡来源自动扩展为“账号全部角色获取历史”。

### 4.3 手工补录

用户可以手工新增角色获取事实。手工记录使用 `UserEntered` 来源，并至少包含：

- 游戏账号和角色稳定 ID；
- 获取原因；
- 获取时间或时间范围；
- 时间精度；
- 可选备注和活动名称。

首批原因：

- `砺行修远活动`；
- `周年庆活动自选常驻五星角色`；
- `周年庆活动自选限定五星角色`；
- `其他`。

选择任一“周年庆活动自选……”原因时，界面必须提供“活动名称”字段；字段值允许留空，留空时使用通用原因名称展示。选择“其他”时必须填写能够说明来源的原因文本。

手工记录允许精确到秒，也允许使用分钟、小时、日期或周精度；周是允许的最低时间精度。周精度保存为明确的周区间，不得虚构为周内某个精确时刻。

经过去重和冲突确认的手工获取事实参与获取序号、首次和满命里程碑计算。修改或删除手工事实必须进入 Revision 和 OperationHistory。

### 4.4 筛选

至少支持：

- 按角色星级筛选；
- 只显示一个或多个指定角色；
- 按账号、时间范围和来源筛选；
- 在默认里程碑和每次获取两种颗粒度之间切换。

## 5. 武器时间线

武器时间线为双模式。

### 5.1 默认颗粒度

- 无论星级，每种武器只显示第一次获取节点；
- 历史不完整时使用“本地首次记录”等措辞；
- 默认不显示精炼达到某一级别的里程碑。

### 5.2 提高颗粒度

- 用户可以查看每次四星或五星武器获取节点；
- 三星武器仍只显示首次获取，避免大量重复节点；
- 抽卡派生节点必须注明只覆盖本地抽卡记录，不代表锻造、活动、纪行、钓鱼、任务或探索来源。

武器允许使用与角色相同的手工时间精度和 `UserEntered` 来源。武器的预定义获取原因目录留待武器领域实现时确定；在此之前使用明确的自由文本原因，不复用角色专属原因枚举。

### 5.3 筛选

至少支持按星级、指定武器、账号、时间范围、来源和颗粒度筛选。

## 6. 挑战时间线

挑战时间线为双模式，覆盖深境螺旋、幻想真境剧诗和幽境危战。

### 6.1 观察事件

每次采集到与该账号、模式和期次已有规范化内容不同的官方记录，就保存一个新的不可变挑战观察，并生成一个挑战时间线事件：

- 相同记录重复采集不产生新事件；
- 只有规范化业务内容变化才产生新事件；
- HTTP 时间、响应顺序或无关传输字段变化不得使内容被误判为新记录；
- 每个观察必须记录 `ObservedAt` 和 `FetchedAt`；
- 历史观察不得被最新状态覆盖，以便查看一期挑战如何逐步完成或提高成绩。

内容判重使用模式、期次自然身份和规范化内容指纹；具体自然键与内容指纹字段在挑战领域 Schema 中冻结。

### 6.2 完成节点

当某一期首次从本地可见状态达到该模式定义的“完成”条件，或首次采集到的记录已经完成时，生成一个完成节点。后续成绩变化继续生成观察事件，但主时间线不再为同一期重复生成完成节点。

“完成”的具体条件由各模式领域规则定义，不能仅以“接口返回了记录”判断。

### 6.3 时间规则

| 模式 | 事实时间 | 采集时间 | 排序规则 |
|---|---|---|---|
| 深境螺旋 | 官方返回的最后完成 Chamber 时间 | 始终保存 | 优先按最后 Chamber 时间 |
| 幻想真境剧诗 | 官方返回的最后完成剧幕时间 | 始终保存 | 优先按最后剧幕时间 |
| 幽境危战 | 当前没有可靠完成时间 | 始终保存 | 按本次采集时间 |

官方未返回可靠发生/完成时间时：

- `OccurredAt` 保持未知；
- 使用 `ObservedAt`/`FetchedAt` 作为 `SortAt`；
- UI 必须标记“采集于”，不得显示成精确完成时间。

## 7. 来源、完整性和序号

- `OfficialApi`、`StandardImport`、`FurinaImport`、`UserEntered`、`Derived` 等来源必须可见且可筛选；
- 无法确定旧记录来源时使用明确的未知来源，不得默认为官方 API；
- 获取序号和满命里程碑是可重建派生结果；
- 序号计算按档案内账号副本进行，不跨档案合并；
- 同一事实被不同来源重复提供时先执行领域合并策略，再生成时间线节点；
- 来源覆盖不完整时，界面必须提示“只基于当前档案记录”。

## 8. 保存与导出

- 领域规范化事实由领域模型和仓库保存；Chronicle 是消费方，不能为查询方便反向塑造事实。
- 抽卡、挑战观察、成就和手工获取事实是规范化领域数据；
- 获取序号、首次、满命和主时间线选择结果是派生投影；
- Portable Dataset 和 Archive 导出领域事实、来源和必要修订，不依赖当前可见 Profile；
- Markdown 可以按主时间线或指定领域时间线生成人类可读报告；
- 修改筛选条件或展示模式不得改变导出事实集合。

Chronicle 不承担领域数据完整导出职责。领域应直接提供适用的 UIGF/UIAF、Furina 机器可读载荷及至少一种 Markdown、文本或表格出口；可读报告可以不可重新导入。时间线报告可以按 Profile 选择叙事内容，但不能替代领域完整导出，也不能使用户只能通过应用 UI 查看自己的数据。

Windows/Android 文件互通是核心需求，自动同步是未来可选能力；以上出口不要求提前实现分布式同步协议。

## 9. 首批验收要求

以下仍是已接受的 Chronicle 产品行为，在 [Phase 8B 计划](../project/PHASE_8B_PLAN.md) 的独立领域能力之后验证；不构成 8B.1 或领域成立的前置条件。真实重要成就目录和未实施模式的完整规则按相应领域实施时点冻结。

- 同一五星抽卡只产生一个主时间线节点，并可显示正确或明确未知的五星间隔；
- 四星角色第 1 次和第 7 次获取进入主时间线，第 2～6 次默认不进入；
- 角色高颗粒度模式可以展开第 2～6 次获取；
- 所有武器默认只出现首次获取，四星/五星可展开每次获取；
- 周精度手工事件以时间范围显示，不产生伪造秒级时间；
- 深境螺旋和剧诗使用最后完成子关卡时间，幽境危战使用采集时间；
- 相同挑战数据重复刷新不新增事件，内容变化新增事件并保留旧观察；
- 同一期挑战只产生一个主时间线完成节点；
- 切换时间线 Profile、视图模式和颗粒度不修改底层记录。

## 10. 后续扩展

成就完整时间线、背包、经济、便签、游玩会话及其他时间线以后分别规划。除非对应规范明确声明为双模式，否则新时间线默认只提供文本视图。
