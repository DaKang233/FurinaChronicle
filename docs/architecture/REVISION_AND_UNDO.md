# 修订、操作历史与撤销

状态：Accepted target

## 三类历史分离

```text
Data Revision / Provenance
    说明数据如何演变以及当前版本从哪里来

OperationHistory
    面向用户的有限撤销栈

ChangeJournal
    未来多端同步的可靠变更序列
```

撤销数量不限制同步 Journal，也不得导致当前记录丢失最低必要来源信息。

## DataChangeSet

一次用户可理解的数据修改形成一个变更集，例如一次导入、一次全量刷新纠正、一次分类覆盖、一次普通删除、一次手工纠正或一次撤销。

建议字段：

```text
ChangeSetId
OperationKind
ArchiveIds
DatasetKinds
StartedAtUtc
CommittedAtUtc
Origin
Summary
AffectedRecordCount
UndoOfChangeSetId
```

覆盖相同记录时形成新 Revision，并关联被替代版本、ChangeSet、来源、时间和原因。当前投影显示有效版本，历史用于审计和撤销。

## 撤销配置

- 按档案分别计数。
- 默认每个档案保留最近 3 个可撤销 ChangeSet。
- 用户可以设置为 `0` 以关闭后续撤销记录，或设置为 `1..1000`。
- 不提供无限撤销；1000 是单档案硬上限。
- 跨多个档案的一次原子操作只有一个 ChangeSet，但在每个相关档案的计数中各占一次。
- 将设置改为 0 不自动删除已有历史；用户可以另行不可逆清空历史。关闭后不再为新操作保存撤销内容。

撤销本身创建新的反向 ChangeSet，而不是抹除历史。超过配置数量的旧操作不再保证可撤销，清理不得改变当前有效状态。

附件和大型 Raw Snapshot 可以作为 ChangeSet 的撤销材料保留，不因体积较大自动排除。

## 存储空间不足

创建新的可撤销操作前应检查或保守估算所需空间。如果空间不足，且继续操作需要删除较早的撤销记录：

1. 明确显示将删除哪些较早 ChangeSet 及大致空间；
2. 只有用户确认后才可清理并继续；
3. 用户拒绝时取消尚未提交的新操作；
4. 清理按最旧优先，并连同只服务于该撤销项的附件或 Raw Snapshot 清理；
5. 当前有效数据、最低来源信息和同步所需 Journal 不得被当作撤销缓存清理。

## 普通删除

普通删除形成可撤销 ChangeSet。未来同步使用可传播 Tombstone 表达普通删除，撤销则产生恢复变更。

## 不可逆删除

不使用“隐私删除”这一名称。不可逆删除：

- 只删除当前本地安装中程序能够管理的具体数据；
- 不删除已导出文件、其他设备数据、云备份或社区统计数据；
- 不传播为远端删除操作；
- 不保留被删除记录的具体内容，因而不能撤销；
- 保留最小 `LocalOnlyTombstone` 和操作记录，例如实体类别、不可反推内容的标识或哈希、删除时间和 ChangeSetId；
- 自动刷新或同步不得在未提示用户时恢复被本地 Tombstone 抑制的数据；显式导入可以在警告后重新引入；
- 清除或替换整个本地数据库后，外部来源仍可能使数据重新出现。

确认界面必须明确说明删除只影响本机，不能承诺影响外部副本。

“类似 Git”只表示变更集、历史和反向操作，不表示分支、任意历史改写或完整 Git 对象模型。
