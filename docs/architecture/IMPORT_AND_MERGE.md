# 导入与合并

状态：Accepted

## 导入阶段

```text
Inspect → Validate → Migrate → Plan → Preview → Apply → Verify
```

- `Inspect`：识别格式、版本、数据集和源档案。
- `Validate`：检查 Schema、必需字段、校验和和内部引用。
- `Migrate`：转换为当前支持的 Portable Model。
- `Plan`：解析档案映射、账号映射、重复和冲突。
- `Preview`：说明每类数据将新增、跳过、覆盖或冲突多少条，并显示名称相似档案和自动改名结果。
- `Apply`：在受控事务中写入并生成 DataChangeSet。
- `Verify`：核对数量、外键、有效修订和导入报告。

验证或应用失败不得留下部分未知状态。全量恢复必须全局原子；普通多数据集导入若允许部分成功，必须事先明确事务边界，并为每个成功单元生成报告。

## 档案名称

名称按完整字符串精确匹配，首尾空白也参与比较。模糊匹配只产生提示和候选，不自动选择。

- 一个精确匹配：默认映射，用户可在预览中改选。
- 没有精确匹配：准备新建，并提示名称类似的已有档案；用户可选择导入已有档案或创建新档案。
- 多个精确匹配：必须手动映射或创建新档案。
- 默认启用唯一名称时，来源内多个同名档案自动添加递增编号，并在应用前提示。

所有新建 Archive 和 GameAccount 都使用目标数据库生成的新本地 GUID。

## 账号映射

`GameRoleIdentityId` 尽量全局保持稳定；`GameAccount.Id` 始终是档案内本地副本 ID。目标档案中不存在相同自然身份时创建副本，已存在时映射到现有副本并执行正常类别合并。

同一个真实角色可以在不同档案存在，各档案副本和数据互不覆盖。共享身份只说明同源，不共享业务记录。

## 类别级策略

- `AddOnly`：默认；只补充目标没有的记录，相同记录保持目标现状。
- `Upsert`：允许源记录覆盖同一逻辑记录，形成修订并可撤销。
- `Manual`：未来能力；逐条或分组决定冲突。

抽卡、成就、挑战、背包快照等数据域各自实现 `IMergePolicy<T>`。无论目标档案是否已有对应账号，都经过同一导入计划、验证和冲突处理流程。

## 删除和幂等性

- 普通导入不因源文件缺少某条记录而删除目标记录。
- `Upsert` 只处理源中明确存在的记录。
- 替换恢复属于全量备份恢复模式，必须单独选择。
- 重复导入同一数据包不得无限增加重复记录或重复修订。
- 自然键、来源记录 ID、内容哈希和 ImportBatch 共同用于识别重复输入。
