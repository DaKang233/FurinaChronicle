# 页面选择状态与跨页刷新

状态：Accepted

## 目的

档案和游戏账号是共享业务数据，但“当前正在查看哪个档案和账号”是页面自己的展示状态。档案管理页、抽卡页以及未来的挑战、角色仓库等业务页可以同时保留不同选择，不能通过共享 ViewModel 或共享可变集合强制同步为同一选择。

## 边界

- `档案与账号管理` 页面负责创建、重命名和不可逆删除档案，以及创建、编辑和不可逆删除游戏账号。
- 业务页面只保留紧凑的档案/账号切换，以及该业务领域自己的采集、导入、导出和展示操作。
- 一个页面改变自己的选择，不得隐式改变另一个已打开页面的选择。
- 业务导入或采集为了完成当前操作而自动创建档案/账号，仍属于该业务流程，不属于常规管理入口。

## 刷新规则

页面实例可以保留所选档案 ID 和账号 ID，但不能长期信任先前加载的实体对象或集合。每次页面重新出现时必须重新查询数据库：

1. 先按页面自己的档案 ID 重新加载档案列表；
2. 档案仍存在时，按页面自己的账号 ID 重新加载账号列表；
3. ID 仍存在时保留选择，并使用最新名称、UID 和区服；
4. 账号已删除时，采用该业务页面声明的安全回退；
5. 档案已删除时，采用该业务页面声明的档案回退；
6. 重新建立领域查询或统计上下文，不继续使用删除前的投影。

当前抽卡页沿用已有 `ArchiveSelectionService` 作为该页面的最后选择与删除后修复来源；档案管理页维护独立的页面内选择，不因查看某个档案而写入抽卡页的选择。

未来业务页如果需要跨启动恢复选择，应使用页面或领域专属的持久化键，不能复用一个全局“当前账号”键来耦合所有页面。

## 实现约束

- 不使用单例共享 ViewModel 在多个业务页面之间传播 `SelectedArchive` 或 `SelectedAccount`。
- 不以显示名称重新识别选择；只使用档案 ID 和游戏账号副本 ID。
- 页面重新出现时的刷新必须能够处理重命名、编辑、创建、删除和外部导入造成的变化。
- 编译和单元测试不能代替页面切换、删除后回退以及移动端导航的实际交互验收。
