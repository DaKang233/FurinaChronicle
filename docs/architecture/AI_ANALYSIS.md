# 可选只读 AI 档案分析

状态：首版实现；授权规则见 [ADR 0027](../decisions/0027-read-only-ai-analysis.md)。不改变 Schema 12、领域事实或 Portable / Archive 格式。

## 使用流程

Windows 侧栏、Android 底部导航新增“AI 分析”。本页有独立的档案和账号选择，不复用其他业务页的选择状态。进入页面会重新读取账号列表。可选整个档案或单账号、UTC 日期范围及抽卡、角色/武器、挑战、历程节点四类资料。

1. 打开“模型服务”，选择 OpenAI 兼容或 Ollama，填写 API 基址、模型及所需密钥。兼容接口基址通常包含 `/v1`，Ollama 原生通常为 `http://127.0.0.1:11434`；路径不自动猜测。
2. “查看模型（不发送档案）”可测试未保存的配置，仅请求模型列表。保存配置后密钥框清空；留空保存保留该接收方原密钥，“移除此服务密钥”删除该密钥。
3. “准备本次资料”仅查询本地。检查“查看资料与证据”，再输入问题，点击“审查并发送”。每次显示接收方、模型和实际消息正文，取消不发送分析资料。
4. 结果流式显示。可继续追问，每次重新审查并确认。点击本地证据查看准备时摘录并检查源记录仍可定位；不会把模型引用本身当成事实正确性的保证。
5. 可主动导出单独的 Markdown 分析报告。会话只在内存，不自动进入领域历史、备份、遥测或下次启动。离页、重新准备、修改范围/模型均取消并清除旧会话。

外部地址必须 HTTPS；HTTP 只允许回环或私网 IP。Android 的系统明文策略仍可能拒绝 HTTP，不代表已通过 Android 私网 Ollama 验收。密钥随 HTTPS 请求发送至用户明确配置的服务。传输不跟随重定向，不使用 Cookie 或系统代理；需代理的环境应配置可直连的服务入口。

## UID 与授权

| 范围 | 实际规则 |
|---|---|
| 单账号 | 无论档案选项如何，始终不发送 UID，以“账号 01”表示 |
| 整个档案 | 默认勾选携带 UID，但每次发送/追问均须在明确说明 UID 的弹窗点击“同意携带 UID 并发送”；关闭弹窗/取消不发送 |
| 整个档案不发 UID | 取消勾选，或在发送弹窗选择“改用编号”。按 UID **数值升序**分配“账号 01、账号 02……”，重新构建资料并再次展示匿名正文，确认后才发送 |

相同 UID 使用本地稳定次序区分副本，不串联账号的抽卡保底；无有效数字 UID 的占位账号排后且不发送占位身份。编号只在本次范围内解释，不充当持久化身份。用户问题中出现当前已知 UID 时转成对应编号，其他长号码、邮箱、URL、本地路径和 GUID 做保守清理。昵称、档案名、自由备注、装备实例标识、外部记录 ID、本地 ID、来源引用和图片 URL 不进模型资料。疑似凭据文本拒绝发送。

这属于去除直接标识，不承诺组合游戏事实完全不可再识别，也不能保证识别任意自由文本中的所有个人信息。用户应检查预览。档案 UID 模式只放行明确的 UID 字段，不因此放开其他身份或凭据。

## 数据边界与保真

`BuildAiContext` 使用专用 `AiContextPacket` / `AiEvidenceFact` 白名单，不能序列化业务对象或 SQLite Row。`AiLocalEvidence` 的账号、源实体和条目映射仅供本地回查，不是 HTTP 载荷。

| 类别 | 首版发送 | 不承诺 |
|---|---|---|
| 抽卡 | 复用 `BuildGachaAnalytics` 的确定性卡池统计；有界的四/五星示例及记录来源 | 全历史、未知首段保底、未来概率保证；跨账号保底合并 |
| 角色/武器 | 最近最多 8 次观察交错选条目，数量/等级/命座或精炼的已覆盖字段；手工获取原因枚举 | 没有保存的天赋、圣遗物、装备细节；自由原因备注 |
| 挑战 | 已保存的观察概要、期次日期、数字统计；每条观察最多 6 组队伍、每组最多 4 人，可信公开名称、等级、命座、试用/自有/助战来源 | 敌方机制和任意富文本、完整关卡、联机队友身份；仅凭满星等推断完成 |
| Chronicle | 已有主时间线的有界派生节点、可信度、来源和抽数证据 | 把派生节点等同完整领域记录，或为 AI 新建投影规则 |

公开物品名称仅从已有可信 `Snap.Metadata` / `GenshinCalculator` 元数据解析，不信任记录中的自由名称；缺失时显示未知角色/武器。分析不主动刷新游戏账号，不读通行证凭据，不下载图片。Chronicle 查询可以更新可重建缓存，不能改变基础事实/Revision。

日期发送 UTC 日粒度，这只是发送精度，不重新解释来源精度。观察与抓取时间分列，未知发生时间为空；不确定/明确区间不能以其起点冒充已知发生日，改在覆盖说明中带区间及原精度。角色和挑战按观察日期筛选，手工获取/抽卡按发生范围，Chronicle 沿用既有查询规则。资料由各领域独立读取，不声明跨领域同时点一致快照。

默认最多 120 条证据、20 个账号，单账号抽卡统计最多 200,000 条；超过要求缩小范围。默认资料 24,000 **字符**，设置范围 4,000～1,000,000；不等于 token 数，也不等于模型 1M token 容量。字符不足删减证据并明确报告，统计与证据样例分开解释；摘要本身超限则拒绝。既有聚合统计、选取样例与未提供领域均不可推导“账号完整”。

## 对话与协议

`AiAnalysisSession` 只接受已确认且未失效的请求草稿。更改账号、日期、类别、配置、离页都会取消旧调用并使草稿失效，晚到数据不得进入新会话。最多保留 12 轮，后续请求只回放最近 4 个完整的问答，单对不超过 12,000 字符；取消、失败、截断及疑似带凭据的旧回答不回放。每次发送正文包含实际回放消息，用户可审查。

输出默认 2,048 token（可设 128～8,192），本地最多 64,000 字符，响应最多 2 MiB、请求最多 8 MiB、总调用 5 分钟。模型列表 30 秒。超限/中断/解析失败/工具调用标为未完成；不自动重试付费请求。只接收文本，不授予工具或数据库权限。

兼容接口使用 `chat/completions` SSE，Ollama 原生使用 `/api/chat` NDJSON、`think=false`、`keep_alive=0`。只有用户勾选“关闭兼容服务的思考模式”才向兼容接口附加 `thinking: { type: disabled }`；其他兼容服务可能不支持，默认不添加。DeepSeek 的相关行为参见[官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。真实 `deepseek-flash` 测试使用这一选项，避免较低额度全部用于思考而没有最终正文。原生 Ollama 可设上下文和 CPU 模式，本轮改用用户提供的外部服务验收，不再启动或下载本地模型。

模型回答明确作为分析展示，系统提示区分事实/计算/推断。`[E001]` 等编号只匹配本次白名单；未知编号警告，不能当成本地有效引用。有效编号也不保证模型论述与原证据相符，仍需人工复核。回答不执行 Markdown/HTML 指令或自动写入事实。

## 组织与设备存储

- Services/Ai：查询白名单、清理、只读证据定位、会话与授权。
- Infrastructure/Ai：HTTP 流式解析、无密钥设备 JSON 设置；密钥通过平台端口隔离。
- Presentation/Ai：双端独立选择/异步状态及通知。
- Windows：独立页面/组合根；`UI4/WinUI/settings/ai/settings.json` 只存服务选项，`keys.bin` 使用当前用户 DPAPI 加密。
- Android：独立导航页；设备 `DeviceAi/settings.json` 和 MAUI SecureStorage。密钥槽绑定协议及规范化服务地址，修改接收方不复用旧密钥。

设备设置、密钥和会话均不进入 Portable / Archive；报告由用户指定保存位置，用户需自行保管。配置和密钥可以不一致保存失败，但后续调用必须明确失败，不能退回其他服务或打印异常正文。诊断只给安全状态/HTTP 码，不记录请求、模型正文、提供商错误正文或秘密。
