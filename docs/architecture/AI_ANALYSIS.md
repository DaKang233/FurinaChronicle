# 本地 AI 聊天与只读档案分析

状态：已实现本地聊天扩展（2026-11-21～22）。[ADR 0028](../decisions/0028-local-ai-chat-and-attachments.md) 替代 ADR 0027 的临时会话限制；逐次授权、去 UID、只读领域和用户自付服务费用继续有效。不改变业务 Schema 12 或 Portable/Archive。

## 页面与使用流程

- Windows“AI 聊天”：左侧会话列表、搜索、新建；右侧消息记录、附件和输入框。支持重命名、置顶、删除、复制、编辑/重新生成、停止、Markdown 导出。Enter 发送，Shift+Enter 换行；可手动回到底部。
- Android“AI 聊天”：通过“对话”打开会话列表，通过顶部菜单管理会话；聊天页底部输入与附件操作。发送审查是独立模态页，系统返回等同取消。
- **模型配置全部在设置页**，聊天页显示当前供应商/模型并提供切换及设置入口。设置包括协议、API 基址、模型、密钥、字符/输出额度、Ollama 上下文/CPU、兼容服务思考开关及图片能力。读取模型列表不发送聊天或档案。
- 无需登录通行证、建立游戏账号或附加档案即可普通聊天。附加文件/图片，或“档案资料”选择本地数据后进行分析。更换/刷新游戏资料另开会话，保留原会话，避免不同事实使用相同 E 编号。
- 每次发送/追问都先展示接收方、模型、实际历史消息、附件摘要和本次省略的旧轮数。确认后先保存待处理消息，再发出请求；取消不新增已发送消息。

## 多供应商和模型

[ADR 0029](../decisions/0029-multiple-ai-providers-and-models.md)：设置页可以添加、编辑和删除多个供应商，分别填写名称、协议、地址及安全密钥；每个供应商可以手动添加多个模型，或点击获取模型列表后选取填写，再保存。模型各自保存别名、模型标识、额度与图片等能力。切换编辑项前先保存当前内容；保存后设为新对话默认选择。当前支持 OpenAI 兼容 Chat Completions 和 Ollama，并不包含 Anthropic 原生或 Responses。

Windows 聊天页点击“切换模型”，Android 点击“模型”，在弹窗/模态页选择供应商和模型。切换不发送请求，原发送审查失效；下一次发送显示实际接收方及历史。各会话保留自己的引用，历史每轮记录当时的供应商名称与模型；旧消息不补造供应商。修改或删除配置不会删除聊天。原配置/模型不存在时先明确提示，发送被阻止，不能静默改投默认供应商。新对话使用设置中的默认选择。

设备配置为内部 Envelope v2，最多 50 个供应商、每个最多 100 个模型、文件不超过 2 MiB，不包含密钥。旧单配置首次读取时进行安全槽复制、原子配置迁移及旧槽清理；失败保留原配置/密钥，损坏或未来版本不得重置。相同地址的不同供应商隔离密钥；改地址或协议不带旧密钥。删除时清理当前地址密钥，但不宣称清除了先前地址遗留安全槽。此内部设置格式不进入领域备份，旧开发版不保证可以读新版设置。

## 会话与本地存储

Windows WinUI：`UI4/WinUI/settings/ai/conversations/<guid>.json`；保留的 MAUI Windows 宿主共享这一聊天目录以维持永久删除保护。Android：`DeviceAi/conversations/<guid>.json`。服务配置和密钥仍是本机设置；MAUI SecureStorage / WinUI 当前用户 DPAPI 分别保护密钥，不进入会话文件。

本地格式是内部 Envelope v1：`version`、`conversation`。内容包括本机会话 ID、标题、置顶、创建/更新时间、清理后的草稿、消息与完成状态、附件副本、准备时只读游戏资料和本地证据映射。它是聊天存储格式，不是 SQLite 行、领域事实、Revision、Portable Dataset 或公开备份协议。文件保持在应用本地；并不承诺磁盘加密，设备访问权限仍需用户自行保护。

每个会话独立原子替换；生成前保存问题，生成中约每 2 秒检查点保存部分回答，完成/停止后保存。重开时未结束的生成标为中断，不冒充完整回答。损坏/未来版本保留原文件并报告，不能静默覆盖。只清理符合本应用精确命名模式、未提交的孤立临时文件；不会自动删除已保存聊天。

本地保留不再限制为 12 轮；单会话最多 1,000 轮、32 MiB，附件累计最多 12 MiB。达到限制提示新建会话，不自动删旧消息。列表读取有 1,000 会话的工程上限。聊天离页/正常关闭时保存并停止生成；尚未进入的页面不能因导航而创建空会话。

编辑某轮或重新生成会建立副本，保留该轮前的上下文，把所选问题和附件放回输入区；原对话保留。删除会话需确认，只删除本机选中聊天和其中的附件副本，不影响原始文件、其他会话或游戏档案。Markdown 导出是单独的人类可读分析报告，图片不内嵌，不可当作可重新导入的完整聊天备份。

## 文件与图片

首轮按维护者确认支持文本、JSON、CSV、Markdown 和图片；另兼容 LOG/XML/YAML 文本。只读取用户通过系统选择器明确选择的文件，不读取正文中的路径、执行脚本、加载远程链接或解压附件。PDF/Word、音视频不在此轮。

- 单文件读取上限 2 MiB；文本须严格 UTF-8 或带 BOM 的 UTF-16，最多 1,000,000 字符。拒绝疑似 Cookie/token/API 密钥内容，清理已知 UID、GUID、长号码、邮箱和路径。JSON/CSV 作为不可信文本提供，不作为业务导入，也不保证清理后仍满足原 JSON Schema。
- 已附加游戏资料时，文件中已知 UID 转成相同账号编号；尚未绑定的长号码只能保守隐藏。若需区分文件中的已知账号，宜先附加档案资料。
- 每次最多 8 个文件、其中最多 4 张静态 PNG/JPEG/WebP，待发送附件合计最多 8 MiB。图片保留像素并移除可识别的 EXIF、文本等容器元数据；不做 OCR。图片像素中的 UID/凭据仍需用户自行裁剪/遮盖，**未确认已去除标识不得发送**。原始文件名和路径不发送给模型。
- 设置页必须明确启用“此模型支持图片输入”。兼容协议发送内嵌 data URL 图片，Ollama 使用原生 base64 images；不上传第三方图床。不支持的模型会明确失败，不私自换服务或降级丢掉图片。
- 文件副本随已发送消息本地保存；重开不依赖原文件仍存在。发送预览显示文本和图片 MIME/大小/SHA 摘要，当前图片可预览；历史图片可从消息附件打开。

SHA 摘要用于标识附件，不是来源真实性或防篡改证明。图片确认属于人工检查；本应用不能保证识别任意图片/自由文本中的全部个人信息。

## 游戏资料、UID 和证据

`BuildAiContext` 继续使用专用白名单：已有确定性抽卡统计、有界四/五星样例、角色/武器观察与手工获取、三类挑战数字概要和队伍、已有主时间线节点。默认最多 120 证据、20 账号，单账号统计最多 200,000 抽；保留来源和覆盖限制，未知字段不补造。公开物品名称来自可信元数据，不信任导入自由名称。日期发送 UTC 日粒度，观察与发生时间分开；区间起点不冒充已知发生日。

| 范围 | 规则 |
|---|---|
| 单账号 | 始终不发 UID，仅编号 |
| 整个档案 | 默认请求携带 UID，但每次发送及追问必须明确同意；授权不持久化为免确认开关 |
| 改用编号 | 按 UID 数值升序编号；使用同一快照改标签，不重分配 E 编号；再次预览并确认后发送 |

已保存匿名快照在重开时保持匿名；档案 UID 会话在重开后仍须逐次授权。为本地定位关联会话，列表可显示/搜索本地 UID，这一列表元数据不进入模型请求。昵称、备注、外部记录 ID、本地 GUID、来源引用和装备实例 ID 继续排除。去标识不等于绝对不可再识别；用户仍需检查实际正文。

模型回复、文件和统计都不写回游戏事实。E 编号只指向本次快照，本地映射不发送。无效引用会提示；有效编号也不能证明模型解释正确。原数据后来纠正时，旧聊天明确仍是准备时摘录，应重新附加新资料，不静默把旧回复改成新事实。

## 永久删除与聊天副本

维护者确认：永久删除游戏数据前提示，并要求用户**先手动处理关联会话**，不自动清除聊天。

记录、账号、档案的永久删除统一在 `SqliteGachaAtomicChangeStore` 进入事务前，通过 `IAiConversationCopyCoordinator` 检查已保存/活动会话。关联游戏快照仍在时拒绝删除，提示进入 AI 聊天按本地 UID 找到并手动删除相关会话。聊天不可读取、无法核实关联时也阻止删除，保留数据。

`JsonAiConversationStore` 的本机协调锁覆盖游戏资料副本的准备/保存与永久删除；这避免了“检查聊天后，又写入删除前资料”的窗口。文件写入锁独立，不持有业务数据库事务做网络请求。Windows 与 Android 生产组合根都注册同一个实例，旧的非 AI 测试调用可不配置此可选端口。普通删除/Undo 不因此变成永久删除；云端/外部导出文件不受影响。

任意用户文件和自由聊天不能可靠自动归属某个游戏账号。这类独立资料需用户自行管理，不能声称已自动清除所有外部文件的相关内容。

## 网络上下文与服务

本地保存与请求打包分离：不再固定只回放最近 4 轮。按配置字符额度选取最新完整问答，最多 120 对；超过额度的更早轮次从本次请求省略，仍完整留在本地。失败/停止/截断的回答不作为完整历史回放。当前问题/附件超限明确拒绝，不静默裁剪。

上下文默认 24,000 字符，可设 4,000～1,000,000；另为系统提示和当前问题保留预算。字符不等于 token，模型 1M 容量不代表默认全部上传。输出 token 范围 128～8,192，本地显示最多 128,000 字符，响应最多 2 MiB、请求最多 24 MiB，总请求 5 分钟。模型列表超时 30 秒。历史图片也计入实际发送预览及总量，超出图片数量/字节范围时停止纳入更早轮次。

服务由用户配置并承担费用。外部服务必须 HTTPS；HTTP 限回环/私网 IP，Android 明文系统策略另需验证。禁用重定向、Cookie 和系统代理。兼容接口使用 Chat Completions SSE，Ollama 使用 NDJSON、`think=false`、`keep_alive=0`。只有明确勾选才发送兼容 `thinking.type=disabled`，其他服务可能不支持。协议依据：[DeepSeek Chat](https://api-docs.deepseek.com/api/create-chat-completion/)、[Ollama Chat](https://docs.ollama.com/api/chat)。

密钥按供应商 GUID、协议/接收方绑定安全槽，模型设置改变使旧草稿失效，但不会删除已存对话。服务错误不记录响应正文、聊天正文、附件或秘密；若提供商意外回显当前实际服务密钥，显示/检查点会遮蔽该值。基础 Markdown 只做安全文字排版、粗体、标题、列表、代码和复制；不执行 HTML/脚本，不自动加载远程图片。

## 范围和验收

当前没有语音、联网搜索、模型工具执行、图像生成、云聊天同步、会话公开交换包、PDF/Word 解析或完整数学/HTML Markdown 渲染。不能把首轮常见聊天能力描述成所有 AI 产品特性的集合。

本轮供应商验收见 [多供应商验收](../development/AI_PROVIDERS_ACCEPTANCE.md)；聊天验收见 [本地 AI 聊天验收](../development/AI_LOCAL_CHAT_ACCEPTANCE.md)。原 [首版只读接入验收](../development/AI_ANALYSIS_ACCEPTANCE.md) 是历史记录。自动化、可见 Windows 交互、Android 编译和 Android 真机分别记录；服务验证仅用合成数据。
