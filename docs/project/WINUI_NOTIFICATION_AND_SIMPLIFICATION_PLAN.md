## 任务目标

用现有通知中心统一呈现 WinUI 中用户需要知道的状态变化，包括应用错误和警告，并同步保存可追溯的本地诊断日志。应用无法继续正常运行时，使用独立的致命错误页。保留诊断报告上传服务端的能力。主页面围绕业务数据、当前范围、筛选条件和操作按钮组织。工作包 1–4 已完成；后续新增范围另行评审。

## 反馈规则

| 场景 | 处理 |
| --- | --- |
| 用户发起的刷新、采集、写入、导入、导出和撤销 | 通知中心显示任务进度和最终结果。同一任务更新同一条通知。完成时提供数量、文件名或必要动作。 |
| 常规加载、切换筛选、翻页和后台重查成功 | 用加载指示、按钮状态、分页数据表达。读取失败或范围失效时发一次通知。用户在提交前主动取消，恢复可操作状态即可。 |
| 空数据、当前选择、记录来源和完整性 | 留在原位置，使用必要的标签和空态。这些是理解数据和作用范围所需的信息。 |
| 表单校验、预览和提交前确认 | 保留在操作现场，包括无效输入、档案映射、覆盖范围、删除、恢复、验证码和第三方发送授权。进入下一步所需的选择必须可见。 |
| 提交成功但页面重载失败 | 显示“已导入 7 条，列表更新失败”，提供重新加载。重试显示时只重新查询，避免重复写入。 |
| 启动阻断或首次接管 | 在主界面尚不可用时提供简短原因和重试、接管等按钮，详细反馈进入同一通知中心。 |
| 应用警告与可处理错误 | 显示在通知中心，同时写本地诊断日志。可继续操作时，通知给出影响和可执行的下一步。 |
| 应用无法正常处理的致命错误 | 先尽力将诊断写入本地日志。通知中心可用时保留对应记录，并显示独立致命错误页。 |

普通成功只更新未读徽标。需立即处理的异常给短提示，可从通知中心查看细节。Debug 可展示阶段、提交号、耗时和已脱敏错误码。普通构建把版本放在“关于”，故障通知只写结果、影响和下一步。两种构建都排除凭据、验证码、完整认证 URL 和未经脱敏的异常。通知历史仅保存在当前会话内，诊断日志单独保存，可跨重启追溯。

## 工作包 1 — 窗口级通知体验（已完成）

1. 复用单例 `INotificationCenter` 和现有 WinUI 面板。有通知时显示铃铛，用户可以打开通知中心。没有任何通知时，两者均隐藏。全部已读后，只要列表还有通知，铃铛仍可打开历史。
2. 为用户主动操作提供稳定的任务标识和更新能力，用于进行中、完成和失败。独立操作各有结果，周期性重复错误继续用现有去重。跨页完成的任务仍能呈现结果。
3. 动作使用当前仍有效的目标，处理动作失败。数据已经提交时只提供重新查询或打开导出文件夹等安全动作。
4. 接入启动警告，随后移除重复 `InfoBar`。验证键盘打开和关闭、焦点返回、读屏播报、窄窗口下的操作可达性。

### 错误、警告与诊断报告

1. 从 WinUI 启动、页面命令、查询、后台任务及宿主级未处理异常入口清点诊断来源。让警告和可处理错误进入统一诊断入口，由该入口写日志并发布通知。通知与日志共用诊断编号。一次故障跨多层传播时只生成一次面向用户的反馈，通知合并后仍可用编号回查发生时间和次数。
2. 将脱敏日志写入本机应用日志目录，记录时间、严重级别、操作、版本、诊断编号、异常类型、错误码和脱敏调用堆栈。沿用现有脱敏和日志设施，补齐滚动和保留上限。日志写入失败时保留可用的通知或错误页，避免递归报错，也不改变已提交的业务结果。
3. 将无法安全继续运行的情况交给独立致命错误页。普通网络失败、可重试的启动阻断和输入错误继续沿用对应业务路径。致命错误页不依赖业务数据库或主窗口导航，提供简短原因、诊断编号、已脱敏的开发者详情，以及复制、导出、退出等可用动作。通知面板、日志写入或页面本身不可用时，尽力保留本地诊断，并由宿主提供最小错误提示后安全退出。
4. 保留上传诊断报告至服务端的功能。实施前核对可复用的上传入口和服务端契约；若本分支缺少实现或已批准的端点，记录缺口并继续完成通知、日志和本地导出。上传前让用户预览将发送的报告并明确确认，上传失败时保留本地报告和重试入口。默认自动上传须另获维护者明确决策和用户明确授权。报告不得包含凭据、验证码、完整认证链接、业务数据库或私人档案内容。

### 界面文案

- 参考 Hutao、FufuLauncher、Starward 中同类页面的文案长度和信息密度。标题说明对象，按钮用明确动词，补充文字通常一句即可。只有影响选择、理解或下一步操作的信息才常驻显示。
- 普通构建启动时省略提交号、阶段和构建过程。需要定位问题时，将这些信息放到关于、Debug 视图、诊断详情或致命错误页。
- 技术原理、格式兼容范围和迁移细节放入帮助文档。诊断收集范围、报告上传及用户数据处理的详细说明放到适用的隐私政策、EULA 或帮助页面。设置默认只显示“导出诊断报告”“清除图标缓存”等操作名称，必要时补一句用户可感知的影响。
- “备份与恢复”默认提供操作按钮、格式名称和必要的选择。完整格式说明通过“了解文件格式”等入口按需展开。需要简短说明时，可写“备份文件可用于恢复”“按所选类别导出”或“Markdown 供阅读”。导入映射、替换范围和实际影响在预览或确认时显示。用户授权上传、覆盖或删除前，仍须看到当前操作的关键影响。

### 设置页面布局

- 参考 Hutao 的设置条目设计。**一个设置项一个条目**，左侧为标题，标题下按需显示一句小字说明，右侧对齐当前值或开关、下拉框等控件。
- 同项含多个相关参数时，默认显示主条目和当前值或简短摘要。展开后显示子项，例如“视频背景”下的“静音”“循环”。参数较多或需要集中编辑时，用条目打开单独弹窗。
- 沿用已有设置及其保存逻辑。检查窄窗口换行、键盘操作、展开收起、弹窗关闭后的焦点恢复和读屏标签。

## 验收与交付

从仓库根目录执行，按当前项目约束配置本机依赖。

```powershell
dotnet test src/FurinaChronicle.Tests/FurinaChronicle.Tests.csproj -c Release -m:1
dotnet build src/FurinaChronicle.Windows/FurinaChronicle.Windows.csproj -c Debug -p:Platform=x64
./eng/Publish-WinUI.ps1 -OutputDirectory ./artifacts/ui-notification-release
./eng/copyright/Manage-CopyrightHeaders.ps1 -Mode Check
git diff --check
```

- Debug 和普通构建分别启动，用独立的 `FURINA_UI1_DIRECTORY` 和合成文件交互验收。若测首次接管，使用显式覆盖的独立生产布局测试根目录和合成库。
- 用 UIA 或人工桌面操作验证成功、失败、取消、重试、去重、切页后完成、未读、动作过期，以及提交成功但重载失败。每个操作应只有一条最终结果。检查通知关闭后的焦点和页面中为已删除文本预留的空间。
- 用合成故障验证警告和可处理错误同时出现在通知中心和本地日志，重启后可通过诊断编号追溯。验证日志轮换、脱敏和日志目录不可写时的降级。模拟无法继续运行的致命错误，核对独立错误页、详情复制或导出以及退出。
- 使用受控端点验证报告预览、确认上传、取消无请求、上传失败与重试。端点或授权缺失时，将上传验收标记为 Blocked，仍需验收本地日志和导出。
- 验证空通知时铃铛和面板均隐藏，首条通知出现后可打开中心，清空后两者再次隐藏。检查普通构建启动页不展示提交号，备份格式说明默认收起，设置条目采用左侧标题和右侧值的布局。记录折叠和弹窗两种设置入口的交互结果。
- 记录提交、配置、场景、证据位置与结果（Pass / Fail / Blocked / Not run）。真实账号、生产库和 Android 的验收按实际授权与设备条件记录。构建通过仅计入构建证据。
- 按工作包提交可独立审查的改动。同步修正第一轮通知文档中与现状不符的描述。提交与推送按维护者对当前任务的授权执行。

本轮作用域为 WinUI 和必要的共享展示与诊断接口。沿用 Core、Services、Infrastructure 的职责划分、业务事务、档案内身份和既有格式。跨重启保留的是本地诊断日志。通知历史持久化、同步和额外遥测另行评审。
