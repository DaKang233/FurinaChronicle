# 项目宪章

状态：Accepted

## 定位

FurinaChronicle 是一个本地优先的原神个人历史数据库。官方服务负责提供当前可查询的数据；FurinaChronicle 负责在用户授权下长期保存这些数据，使其在几年后仍可查询、迁移和分析。

## 核心目标

- 持续保存抽卡、成就、挑战、角色、武器、背包、经济流水、便签和游玩会话等数据。
- 清楚区分官方证据、外部导入、本地观察、用户输入和派生结果。
- 允许用户在 Windows、Android 及未来平台之间迁移数据。
- 对有社区标准的数据优先实现标准格式的完整导入和导出。
- 支持完整备份、分类导出和不可导入的 Markdown 报告。
- 无服务端、无账号和离线时，核心档案能力仍可使用。

## 核心价值

1. 数据首先属于用户。
2. 历史可追溯比短期便利更重要。
3. 不确定性必须显式表达。
4. 可迁移性高于对当前数据库结构的便利依赖。
5. 失败不得破坏已经持久化的用户数据。

## 维护方式

项目目前由单人主维护。流程应优先帮助维护者和 Agent 保持长期一致性，而不是模拟大型团队审批。不可逆或长期兼容决策使用简短 ADR；普通内部实现不要求额外审批文件。

## 服务端定位

服务端是可选扩展，不是客户端核心的前置条件。未来可以提供：

- 云端备份；
- 多设备增量同步；
- 公共元数据；
- 用户主动参与的大规模抽卡或挑战统计。

这些能力必须保持独立授权和独立接口。统计服务不得默认读取私人备份，客户端也不得因服务端不可用而失去本地档案能力。
