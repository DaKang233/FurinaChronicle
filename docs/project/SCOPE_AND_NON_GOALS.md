# 范围与非目标

状态：Accepted

## 核心范围

产品定位和四项原则以 [项目宪章](PROJECT_CHARTER.md) 为准：当前产品范围是本地优先的原神个人历史档案工具，遵循领域自治、数据优先、开放导出、Chronicle 派生。共享基础允许未来按实际需求扩展其他游戏，但其他游戏不自动进入当前核心交付范围。

- 米游社与 HoYoLAB 账号登录、凭据维护及角色查询。
- 一个或多个玩家档案及其独立的游戏账号数据副本。
- 数据采集、标准导入、专用数据集导入和手工录入。
- 抽卡、角色、武器、挑战、成就、背包、资源流水、便签状态和游玩记录等可可靠取得的数据；按实际采集能力逐领域实施。
- 各领域独立的本地查询、历史查看、展示、统计和报告。
- UIGF、UIAF 等通用标准的优先导入和导出。
- Furina 机器可读格式承载标准无法表达的数据，支持分类备份、迁移和最终全量 Archive。
- Markdown、文本、表格等可脱离 UI 查看和分析的人类可读导出，可以不可重新导入。
- Chronicle 对已有事实进行筛选和组合；它不承担领域数据完整导出职责。
- Windows 与 Android 之间的文件级互通。

## 可选扩展

- 按实际需求逐步接入其他游戏；首个潜在扩展为《崩坏：星穹铁道》，预计优先通过 UIGF 接入抽卡记录。
- 云备份和多端自动同步。
- 本地游戏数据采集器，例如可选的 Yae 适配器。
- 社区挑战或抽卡统计。
- 公共元数据分发。
- Windows 游戏游玩时长采集。

可选扩展不得反向成为核心功能的必要依赖。

接入新游戏时优先复用已经验证为同义的共享身份、Portable、导入导出和领域基础能力，并为该游戏增加独立适配器或领域实现。不得要求当前 Phase 预先统一所有未来游戏的角色、装备、挑战、背包和资源模型。星穹铁道 UIGF 抽卡是潜在首个纵切，不代表已承诺同时接入其账号 Provider、其他数据域或完整 UI。

游玩记录属于计划记录的数据范围；具体 Windows/Android 采集方式仍按平台能力选择，不因此引入高级启动功能。Windows 与 Android 文件互通不以自动同步上线为条件。

## 非目标

- 不开发高级游戏启动、安装、更新、修复、注入或启动参数管理体系。
- 不将 FurinaChronicle 设计为必须在线或必须登录 Furina 账号的应用。
- 不承诺能恢复用户首次使用 FurinaChronicle 之前已被官方删除的历史。
- 不假设所有数据都能从米游社或 HoYoLAB 获取；不同领域可以使用不同 Provider。
- 不将显示名称或本地元数据当作官方稳定身份。
- 不默认收集遥测、统计投稿或凭据。
- 不建设面向任意游戏、Provider 或数据域的通用历史数据平台。
- 不为尚未实施的游戏预建空领域、统一全部业务 Schema，或把推测中的跨游戏共同点冻结为当前契约。
- 不为未来自动同步提前实现完整分布式协议或冲突框架。
- 不要求所有领域或所有长期记录进入 Chronicle；背包、流水和高频观察可以主要服务领域查询、统计与导出，保留策略独立于时间线可见性。
