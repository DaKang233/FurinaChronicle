# UI-6 无障碍与性能记录

状态：Accepted（2026-11-13）。环境：Windows 11，默认 WinUI 3 宿主 `0.10.0 (Phase 10.0)`，
解开包发布（self-contained），隔离数据目录。测量脚本（本地、Git 忽略）：
`artifacts/lead-ui6/Test-Ui6Audit.ps1`、`Test-Ui6Keyboard.ps1`。

## 启动与页面切换

| 指标 | 结果 | 说明 |
|---|---|---|
| 主窗口出现 | 约 0.5–0.9 s（典型） | 含 Windows App SDK 初始化；并发编译时出现过 9 s 异常值 |
| 概览就绪（计数可见） | 约 1.5–5.8 s（典型） | 首次运行需创建隔离库并播种 3 档案/4 账号/71 记录；同目录后续启动更快；并发构建时出现 10 s 异常值 |
| 概览 → 游戏历程 | 约 0.12 s | 页面切换 + 首次查询 |
| 概览 → 抽卡 / 角色武器 / 挑战 / 档案 / 历史 / 登录 / 设置 | 约 0.02–0.13 s | 已构建页面切换；查询走异步加载 |

结论：常规交互无卡顿；启动成本主要来自首次隔离库播种与 Windows App SDK 初始化。上述异常值出现在
与本机其他构建任务并行时，最终发布前的回归需在空闲环境复测并记录基线。

## 无障碍（UIA 自动化）

对 9 个页面枚举 Button/Edit/ComboBox/CheckBox/RadioButton/ListItem/Slider：

- 交互控件共约 210 个；**可访问名称缺失从 1 降到 0**：
  - 唯一缺陷：游戏历程页 Markdown 报告只读 TextBox 只有 AutomationId、无 Name；
  - 修复：`ChroniclePage.xaml` 增加 `AutomationProperties.Name="Markdown 报告（只读）"`，
    重新发布后该页 `missingName=0`。
- AutomationId 缺失：抽卡页 25、概览 8、档案页 6、历史页 2（其余页面 0）。
  AutomationId 不是屏幕阅读器必需项（这些控件都有可见/可访问名称），主要用于自动化测试定位；
  新交付的 UI-4/UI-5 页面全部 0 缺失。后续新增控件继续要求 Name + AutomationId。
- 键盘遍历：概览页连续 60 次 Tab 命中 8 个不同焦点目标并稳定循环（导航关闭按钮、导航项、
  概览卡片、最近活动、继续查看、刷新、备份与恢复），无焦点丢失/困在不可见控件。
  WinUI `NavigationView` 的其余项按框架约定用方向键在导航区内移动，属预期行为。
- 高对比度/缩放：布局使用主题资源与 `TextWrapping`；未发现固定像素高度裁切新增页面。
  未在真实触摸/屏幕阅读器（Narrator）下做人工走查，列为发布前人工检查项。
