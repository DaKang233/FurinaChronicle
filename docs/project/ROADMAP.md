# 路线图

状态：Target

## Phase 8A：抽卡系统稳定

- 完成现有抽卡刷新、导入、导出、统计和页面稳定性修复。
- 固化全量刷新纠正相同记录的行为。
- 控制大数据页面内存和加载范围。
- 当前状态：功能基本完成，进入软冻结；按 [Phase 8A 退出评审](PHASE_8A_EXIT_REVIEW.md) 完成 Windows 人工验收后正式关闭。

## Phase 8B：Portable Core

- 冻结身份、时间、来源和修订语义。
- 建立数据集版本、验证、迁移、导入、导出和合并接口。
- 建立操作历史和可配置撤销策略。
- 建立 Chronicle 跨数据域投影契约。
- 基础架构完成后，以角色/武器状态仓库和挑战记录两个窄纵切提前验证，不要求同时完成完整 UI 和在线采集。
- 具体工作包见已接受的 [Phase 8B 实施计划](PHASE_8B_PLAN.md)；先执行 8B.0 契约冻结，再开始数据库迁移和新领域代码。

## Phase 8C：首个跨端闭环

- 当前 UIGF 标准的完整导入和导出。
- Furina 全量 Archive。
- 抽卡 Markdown 报告。
- Windows 与 Android 双向往返验证。

## Phase 9：统一采集框架

- 认证、角色解析、数据采集和本地采集器使用小能力接口。
- 统一限流、重试、刷新批次、原始证据和保留策略。
- 优先接入角色/武器状态与挑战 Provider，使 8B 的本地纵切成为可实际刷新的功能。

## Phase 10：角色、武器、战绩与挑战产品化

- 完善角色和武器长期状态观察、比较、查询和 UI。
- 完善深境螺旋、幻想真境剧诗和幽境危战历史查询。
- 引入版本化元数据支持。

## Phase 11：成就与领域深化

- UIAF 导入、导出及成就档案。
- 根据真实采集结果补齐挑战版本差异、历史展示和 Chronicle 聚合。

## Phase 12：背包与经济数据

- 背包快照和差异。
- 原石、摩拉等官方可见范围内的收支记录。

## Phase 13：便签与游玩会话

- 日常、周常和实时便签观察。
- Windows 游玩会话；Android 能力视系统权限和可行性决定。

## Phase 14：同步协议

- ChangeJournal、设备游标、Tombstone、冲突和 Transport 抽象。
- 不要求同时上线云服务。

## Phase 15：可选服务端

- 云备份优先。
- 自动同步其次。
- 社区统计独立规划、独立授权。
