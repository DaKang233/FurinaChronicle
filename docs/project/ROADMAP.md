# 路线图

状态：Target

路线图服务“本地优先的原神个人历史档案工具”，遵循领域自治、数据优先、开放导出、Chronicle 派生。每个领域先独立保存、查询、查看历史和导出，再决定哪些事实参与 Chronicle；不为未来同步提前建设通用框架。

## Phase 8A：抽卡系统稳定

- 完成现有抽卡刷新、导入、导出、统计和页面稳定性修复。
- 固化全量刷新纠正相同记录的行为。
- 控制大数据页面内存和加载范围。
- 当前状态：已于 2026-10-04 完成自动化验证和 Windows、Android 人工验收并正式关闭；后续只进行维护性修复，详见 [Phase 8A 退出评审](PHASE_8A_EXIT_REVIEW.md)。

## Phase 8B：多领域共享基础与独立纵切

- 建立足以承载多个独立游戏历史数据领域的共享基础，用不同领域证明独立保存、查询、导出和参与 Chronicle。
- 8B.0 仅冻结已存数据解释、跨端身份、公开格式兼容和不可逆数据安全所需的最小共享契约。
- 8B.1～8B.3 建立共享 Identity/Time/Provenance、领域 Portable/Export 和 Revision/OperationHistory。
- 8B.4 保持 Gacha 独立能力并适配共享基础；8B.5 提前建立角色/武器和挑战的独立窄纵切，允许 fixture 输入，不要求完整 UI/API。
- 8B.6 在领域独立保存、查询和导出后验证 Chronicle 消费；8B.7 汇总迁移、平台和回归门槛。
- 具体字段、领域 Schema 和 Chronicle 查询细节在对应工作包首次持久化/公开使用前冻结，详见 [Phase 8B 实施计划](PHASE_8B_PLAN.md)。完整 Archive 和未来 Sync 不阻塞当前领域。
- 当前状态：In progress；8B.0～8B.3 已完成，8B.4 的 P0/P1/P3～P7 已完成代码和自动化，P2 大包有界导入与 P8 双端真实文件验收尚未关闭；主数据库为 Schema 5。

## Phase 8C：首个跨端闭环

- 当前 UIGF 标准的完整导入和导出。
- Furina 全量 Archive。
- 将 8B 领域导出形成可直接使用的产品流程，完善抽卡 Markdown 报告；不把可读导出首次验证推迟到本阶段。
- Windows 与 Android 双向往返验证。

## Phase 9：统一采集框架

- 认证、角色解析、数据采集和本地采集器使用小能力接口。
- 仅抽取实际 Provider 的共同能力，不先建设任意 Provider 插件平台。
- 统一限流、重试、刷新批次、原始证据和保留策略。
- 优先接入角色/武器状态与挑战 Provider，使 8B 的本地纵切成为可实际刷新的功能。

## Phase 10：角色、武器、战绩与挑战产品化

- 完善角色和武器长期状态观察、比较、查询和 UI。
- 完善深境螺旋、幻想真境剧诗和幽境危战历史查询。
- 引入版本化元数据支持。
- 完善领域标准/Portable 及人类可读导出；Chronicle 只消费适合叙事的节点。

## Phase 11：成就与领域深化

- UIAF 导入、导出及成就档案。
- 独立成就历史查询、可读导出和重要成就分类目录，目录在本领域实施前冻结。
- 根据真实采集结果补齐挑战版本差异、历史展示和 Chronicle 聚合。

## Phase 12：背包与经济数据

- 背包快照和差异。
- 原石、摩拉等官方可见范围内的收支记录。
- 独立查询、统计、历史比较和开放导出；不要求全部快照或流水进入 Chronicle。

## Phase 13：便签与游玩会话

- 日常、周常和实时便签观察。
- Windows 游玩会话；Android 能力视系统权限和可行性决定。
- 先保存可靠观察并提供领域查询/导出，按领域保留策略处理高频数据，不按时间线可见性决定保留。

## Phase 14：未来可选同步协议

- ChangeJournal、设备游标、Tombstone、冲突和 Transport 抽象。
- 不要求同时上线云服务。
- 仅在启动该可选能力时冻结完整分布式语义；不反向要求 Phase 8B 完成设备游标、网络冲突或完整 Journal。

## Phase 15：可选服务端

- 云备份优先。
- 自动同步其次。
- 社区统计独立规划、独立授权。
