# 路线图

状态：Target

## Phase 8A：抽卡系统稳定

- 完成现有抽卡刷新、导入、导出、统计和页面稳定性修复。
- 固化全量刷新纠正相同记录的行为。
- 控制大数据页面内存和加载范围。

## Phase 8B：Portable Core

- 冻结身份、时间、来源和修订语义。
- 建立数据集版本、验证、迁移、导入、导出和合并接口。
- 建立操作历史和可配置撤销策略。

## Phase 8C：首个跨端闭环

- 当前 UIGF 标准的完整导入和导出。
- Furina 全量 Archive。
- 抽卡 Markdown 报告。
- Windows 与 Android 双向往返验证。

## Phase 9：统一采集框架

- 认证、角色解析、数据采集和本地采集器使用小能力接口。
- 统一限流、重试、刷新批次、原始证据和保留策略。

## Phase 10：角色、武器与战绩

- 长期保存角色和武器状态观察。
- 引入版本化元数据支持。

## Phase 11：挑战与成就

- 深境螺旋、幻想真境剧诗和幽境危战历史。
- UIAF 导入、导出及成就档案。

## Phase 12：背包与经济数据

- 背包快照和差异。
- 原石、摩拉等官方可见范围内的收支记录。

## Phase 13：便签与游玩会话

- 日常、周常和实时便签观察。
- Windows 游玩会话；Android 能力视系统权限和可行性决定。

## Phase 14：同步协议

- ChangeJournal、设备游标、Tombstone、冲突和 Transport 抽象。
- 不要求同时上线云服务。

## Phase 15：可选服务端

- 云备份优先。
- 自动同步其次。
- 社区统计独立规划、独立授权。
