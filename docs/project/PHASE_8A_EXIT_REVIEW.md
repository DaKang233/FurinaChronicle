## 正式关闭前的人工验收

优先在 Windows 执行：

1. 启动应用并选择真实或脱敏测试档案；
2. 在账号模式和档案模式分别打开五个抽卡页面；
3. 重复切换总览、明细、历史、日历和物品页至少 10 轮；
4. 在总览页切换档案模式、收起统计栏并改变窗口宽度；
5. 验证五星历史按时间倒序，同行从左到右、再从上到下；
6. 修改明细每页数量并翻页，返回页面后再次加载；
7. 分别执行一次增量刷新和一次全量刷新，核对重复记录处理；
8. 执行 UIGF 导入、导出并用项目自身重新导入验证；
9. 清除图标/横幅缓存后重新加载，确认失败时文字仍可用；
10. 观察异常日志、进程退出码和内存：不得出现未处理异常或持续无界增长。

Android 的安装和基础启动构建仍应保持通过，但本次 8A 正式关闭以 Windows 运行时问题清零为优先；完整跨端往返属于 Phase 8C。

## 已知非阻塞限制

- 当前内置卡池事件基线主要覆盖已验证的国服数据；国际服不得强制匹配；
- 在线公共元数据更新尚未实现，内置数据仍可离线工作；
- 当前抽卡记录只有单一业务时间，旧数据来源需要在 8B 迁移中以 `Unknown` 等安全默认值处理；
- 性能结论仍需以真实大档案在 Release/接近 Release 条件下验证，调试器内存值只能作趋势参考。

## 退出条件

满足以下条件后可将 Phase 8A 标记为 Closed：

- 自动化测试、Windows 构建和 Android 编译基线通过；
- 上述 Windows 人工验收没有阻塞性问题；
- 未处理异常日志为空，或所有异常均有明确结论；
- 当前实现和本评审形成可追溯提交；
- 新功能请求默认进入 8B 或后续阶段，不再回填 8A。
