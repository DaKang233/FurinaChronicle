## 当前确认项

暂无。

Phase 8B 可以从 8B.0 契约冻结开始；数据库迁移、公开格式实现和新数据域业务代码仍必须等待对应字段、自然键与迁移 fixture 在 8B.0 中冻结。这是实施门槛，不是尚未确认的产品方向。

### 8B.0 必须冻结但不需要重新决定产品方向的实现契约

- 手工角色/武器获取事实的稳定自然键、重复判定和冲突合并规则；
- 秒至周精度的序列化形式、周边界采用的时区/周起始日；
- 三种挑战各自的“完成”判定、期次自然键以及内容指纹包含/排除字段；
- 时间线 Profile 与投影版本的机器可读标识；
- “重要成就”元数据的版本、分类键和维护来源。

这些项目应通过 Schema、fixture 和代码评审冻结；如果实现选择会改变本文件已经接受的用户可见语义，再升级为新的维护者确认项。

## 已确认事项

Q01～Q06 已由维护者确认：

- Q01：`GameRoleIdentityId` 尽量保持全局稳定。
- Q02：撤销次数按档案计数。
- Q03：档案名称使用包含首尾空白在内的精确匹配；模糊匹配只用于导入前提示。
- Q04：不提供“隐私删除”概念；提供只影响本地可管理数据的不可逆删除。
- Q05：取消无限撤销，单档案上限 1000 次，并允许完全关闭撤销功能。
- Q06：接受 ADR 0009 的 Chronicle 派生投影方案，并采用“先完成跨领域基础架构，再提前实现角色/武器状态仓库和挑战记录窄纵切”的 Phase 8B 顺序。

这些决定已经写入身份、导入、撤销、测试和 ADR 文档。
