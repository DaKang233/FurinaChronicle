# ADR 0010：经过筛选的多时间线产品模型

状态：Accepted

## 背景

FurinaChronicle 会长期保存大量规范化记录、状态观察和派生差异。如果把每条记录都直接放进同一条时间线，重要历程会被高频观察、重复采集和普通物品淹没，也无法满足角色、武器和挑战各自不同的查看颗粒度。

## 决定

Chronicle 最终提供多条用途明确的时间线，而不是一条包含所有事实的无限列表。

- 主时间线只显示重要事件节点，默认使用时间轴/图表，并提供文本或表格视图；
- 角色、武器和挑战使用各自的领域时间线；
- 角色、武器和挑战时间线支持时间轴与文本两种模式；
- 以后新增但未明确声明为双模式的时间线，默认只提供文本视图；
- 显示颗粒度属于查询和投影配置，不改变底层规范化记录；
- 未进入主时间线的记录仍可以在领域详情、统计、导出和其他时间线中使用。

主时间线首批重要节点包括：

- 每次获得五星物品；
- 四星角色首次获取和第七次获取（满命）里程碑；
- 完成一期深境螺旋、幻想真境剧诗或幽境危战；
- 被版本化元数据标记为重要的成就，通常包括标志魔神任务完成的成就。

## 原因

- Chronicle 的价值是呈现长期历程，而不是复刻所有数据库行；
- 不同数据域对“重要”和“完整”的定义不同；
- 同一份规范化数据需要支持默认简洁视图和用户主动提高颗粒度；
- 投影配置可重建，适合离线优先、导出和未来多端同步。

## 后果

- `ChronicleEntry` 与“默认可见”不是同一概念；时间线 Profile 决定条目是否显示；
- 采集批次、重复响应和没有变化的状态不得仅因被请求过就生成玩家历程节点；
- 手工补录的角色或武器获取是 `UserEntered` 规范化事实，必须保存原因、时间精度和修订历史；
- 主时间线和领域时间线必须共享身份、来源及时间语义，不能各自发明不可互通的事件模型；
- 时间线视图不得成为业务事实的唯一存储位置。

## 测试要求

- 默认主时间线不会显示三星抽卡、普通四星武器或无变化采集；
- 提高颗粒度只改变查询结果，不创建或删除底层抽卡记录；
- 同一角色首次获取和第七次获取在默认角色时间线中各出现一次；
- 手工获取事件保留来源、原因和秒至周的时间精度；
- 相同挑战响应重复采集不新增事件，规范化内容变化时新增观察事件；
- 没有官方发生时间的挑战以采集时间排序并明确标记为观察时间。
