# ADR 0016：角色／武器状态观察与手工获取事实

状态：Proposed

日期：2026-10-18

## 背景

8B.5 首次保存角色／武器长期状态及非抽卡获取事实。类型身份、观察完整度、无实例 ID 武器、周精度和 Portable 历史范围一旦落库或导出，后续修改会改变已有数据解释，必须在首次持久化前明确。

## 建议决定

- 状态观察归属于档案内 `GameAccountId`。角色／武器使用稳定类型 ID；观察使用独立 `ObservationId`，内容指纹不充当身份。
- 观察同时声明集合覆盖与条目字段覆盖。集合 `Complete` 只表示声明项目种类在本次范围内枚举完整；条目 `Complete` 只表示声明字段集完整，两者不得相互提升。
- 无可靠武器实例 ID 时保存类型汇总及数量；等级、精炼等实例属性保持未知，不按输入顺序建立实例轨迹。
- 手工事实使用稳定 `AcquisitionId`。角色原因使用已接受目录，武器使用非空自由文本；来源为 `UserEntered`。
- Week 为周一 00:00 开始的七日 `[start,end)` 日历区间。保存用于计算边界的明确偏移；首版默认 UTC+8，但不得在读取时按设备时区重算。
- Portable 首版携带全部不可变状态观察，以及手工获取当前事实和可追溯修订链；不携带本机 Undo 槽、UndoLimit、OperationId 重试结果或 LocalOnlyTombstone。
- 同一 Portable 稳定 ID 和相同内容为 NoOp；同 ID 不同内容在 AddOnly 下为 Conflict。明确纠正通过领域 Upsert 形成 Revision，不由导入顺序裁决。

## 后果

- Partial 中缺少项目或字段不会清零已有知识；比较只能对可比字段生成 Derived 结果。
- 首次状态观察不能证明获得时间；状态观察和手工获取不自动与 Gacha 合并。
- Portable 可以迁移来源历史，但目标设备仍产生独立接收 Receipt 和本地 ChangeSet。

## 确认前限制

本 ADR 未经维护者确认时不得标记 Accepted，不得创建依赖上述编码的生产 Schema 或宣称对应 Portable 格式稳定。纯模型、反例和协调器可以先行。
