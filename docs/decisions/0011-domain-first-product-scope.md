# ADR 0011：领域优先的产品定位与 Phase 8B 范围

状态：Accepted

确认日期：2026-10-04

## 背景

维护者明确 FurinaChronicle 的定位为“本地优先的原神个人历史档案工具”。记录可可靠取得的数据、独立查看各领域历史、开放导出和 Windows/Android 文件互通是核心需求。原计划把整个 Chronicle 草案及尚未实施领域的细节集中到 8B.0，容易把领域建设变成通用数据平台或未来同步框架建设。

## 选项

1. 先冻结所有领域、Chronicle 与未来同步的完整契约，再建设领域。
2. 仅为当前数据安全和跨端解释冻结最小共享契约，领域先独立成立，Chronicle 后消费。

## 决定

采用选项 2，并统一四项原则：领域自治、数据优先、开放导出、Chronicle 派生。

- 各领域自行管理规范化事实、持久化、历史、查询和导出；Contributor 不是领域成立的必要条件。
- 有标准时优先标准；Furina 机器可读格式补足标准不能表达的数据并服务文件迁移与备份；人类可读导出服务查看、归档和外部分析，可以不可重新导入。
- 共享基础仅承载当前实际需要的 Identity、Time、Provenance、Completeness 和合并/修订基本语义，不要求领域实现完整分布式同步协议。
- 可修改事实的稳定身份不得因修改时间、原因或其他内容而改变；内容判重与实体身份分开。具体键和字段在对应领域持久化或公开导出前冻结。
- 数据库仅在确认是新空库时初始化；已知旧版使用显式安全迁移。未知/未来版本或 application ID 不匹配时停止写入并保留原库，不得以删表重建代替失败处理。具体迁移算法及 fixture 在迁移实施前落实。
- 8B.0 仅阻塞会影响已存数据无损解释、跨端实体身份、公开格式兼容或不可逆数据安全的共享问题。其余细节归对应工作包，在首次涉及持久化/公开格式时仍必须冻结。
- Chronicle 的 EntryId、ProjectionSequence、Profile 和游标属于 Chronicle 子系统；不得成为其他领域保存、查询或导出的前置条件。

## 原因

先交付用户能够带走和分析的数据，同时保持未知信息真实、旧数据安全和跨端语义一致。避免单维护者项目为假设性的领域、Provider 或同步能力建立过大框架。

## 后果

Phase 8B 依次建立最小共享基础、领域 Portable/Export、Revision/OperationHistory、Gacha 适配及角色/武器和挑战独立纵切，再验证 Chronicle 综合消费。完整 Archive 容器仍在 8C，完整同步语义仍在未来可选的 Phase 14。

本决定补充 ADR 0001、0003、0009 和 0010 的作用域，不撤销既有 Identity、Time/Provenance、Import/Merge、Revision/Undo、Compatibility Policy 或 Chronicle 产品行为。8B.0 的细化门槛与后续工作包见 [Phase 8B 实施计划](../project/PHASE_8B_PLAN.md)。

## 迁移影响

本次只修改文档，不迁移数据库，不发布新格式。现有 Schema 2 的实现差距仍需通过后续代码和迁移测试修复；已被旧代码丢弃的信息不得假装可以恢复。

## 测试要求

- 不启用 Chronicle 时，领域仍能保存、查询、查看历史和导出。
- 修改事实内容、跨端导入和账号副本重映射不使同一事实被误判为新实体。
- 未知数据库、未来版本、迁移失败及损坏文件不破坏原数据。
- 导出和重导入不依赖 SQLite 行或 Chronicle 索引；人类可读导出保留时间、来源与范围说明。
- Chronicle 的确定性、重建、多 Profile 和已接受默认节点行为继续按 ADR 0009、0010 验证。
