# 测试要求

状态：Accepted

这些是对应能力实现时的验收要求，不表示当前已有实现或 fixture。实施范围按 [Phase 8B 计划](../project/PHASE_8B_PLAN.md) 分包；Chronicle、完整 Archive 和未来 Sync 的测试不得被提升为所有领域或整个 8B.0 的前置条件。

## 领域自治与开放导出

- 禁用 Chronicle 或删除投影索引后，领域仍能保存、查询、查看历史和导出全部适用数据。
- 首批角色/武器和挑战纵切分别验证输入、持久化、独立 Query/History、至少一种人类可读 Export，以及 Portable 重导入。
- 没有 Contributor 的领域不因此缺少成立资格；Profile 不决定底层数据保留。
- 可修改事实内容变化不改变稳定身份；内容判重不代替身份或静默合并疑似重复。
- 人类可读输出可脱离 UI 查看，保留账号范围、来源、时间精度、不完整与派生说明，不要求可重新导入。

## 身份与档案

- 同一自然角色可以在两个档案创建不同 `GameAccount.Id`，共享稳定 `GameRoleIdentityId`，记录互不影响。
- 同一档案不能创建第二个相同自然身份副本。
- 导入时源本地 ID 被重映射；稳定身份 GUID 在无冲突时保留。
- 同 GUID 指向不同自然身份时导入失败并报告身份错误。
- 目标已有账号时仍执行完整类别合并和报告。

## 档案名称

- 精确匹配保留首尾空白和大小写差异。
- 模糊名称只产生提示，不自动映射。
- 唯一名称选项默认开启，手工创建和重命名拒绝精确同名。
- 来源内多个同名档案自动编号，编号结果稳定且在预览中可见。
- 已有同名档案时不能开启唯一选项。
- 选项开启后若数据库出现重复，启动被阻塞；修复并重启后恢复。
- 唯一选项关闭且存在多个同名候选时，必须手工映射或新建。

## 导入与修订

- `AddOnly` 不覆盖相同记录；`Upsert` 生成修订并允许撤销。
- 不同类别可以选择不同策略，重复导入幂等。
- 导入中断不留下无法识别的部分状态。
- 普通导入不会因源数据缺失删除目标记录。

## 操作历史

- 撤销按档案计数，默认 3 次。
- 0 表示停止记录新撤销项，1～1000 均有效，1001 被拒绝。
- 跨档案原子 ChangeSet 在各相关档案中各占一次，但只提交和撤销一次。
- 附件和大型 Raw Snapshot 可以支持撤销。
- 空间不足时，不经确认不得清理旧历史；拒绝清理则新操作不提交。
- 清理旧历史不改变当前记录，也不影响尚未确认的 ChangeJournal。

## 不可逆删除

- 删除后具体本地数据和可恢复 Revision 不再存在。
- 保留的 LocalOnlyTombstone 不含具体记录内容。
- 删除不生成远端 Tombstone，不修改导出文件、模拟云备份或其他设备 fixture。
- 自动刷新不静默恢复被抑制数据；显式导入需要警告和确认。

## Portable Dataset 与 Archive

- Schema 验证覆盖必需字段、未知字段和未知枚举。
- 旧版本通过 Migrator 得到当前模型；未知未来 major 被拒绝且数据库不变。
- 哈希错误和截断文件不会改变数据库。
- 大型 NDJSON 流式处理，不要求一次加载全部记录。
- Windows 导出、Android 导入并重新导出后语义一致；反向同样成立。
- 普通 Archive 不包含凭据、DeviceId、平台 URI 或游戏路径。

## Chronicle 时间线

本节在领域独立能力之后、8B.6 Chronicle 验证时执行。AsOfSequence 等字段是当前草案方案的标识，具体子系统契约须评审冻结；稳定分页行为要求继续有效，不把字段名当作已发布共享格式。

- 同一规范化记录重复投影产生相同 `ChronicleEntry.EntryId` 和排序键。
- 瞬时、区间和不确定区间不会丢失时间精度或原始偏移。
- `OccurredAt`、`ObservedAt`、`FetchedAt` 和 `ImportedAt` 不得互相替代。
- 同一时刻的多条记录使用复合游标稳定分页，不重复、不遗漏。
- 分页期间插入发生时间较旧的新投影时，既有游标仍受同一 `AsOfSequence` 约束，不漂移到新记录。
- 档案查询保留每条记录的 `GameAccountId`，不同档案的账号副本不隐式合并。
- 官方、标准导入、本地观察、手工和派生来源在投影中保持可区分。
- 投影或索引删除后能从规范化记录重建。
- 修订、撤销和不可逆删除后，默认游戏历程只反映当前有效事实。
- 抽卡、角色/武器状态和挑战 fixture 分别覆盖精确事件、不确定变化和周期记录。
- 主时间线默认只显示每次五星物品、四星角色第 1/7 次获取、每期挑战完成和重要成就；普通抽卡、无变化采集不进入默认结果。
- 五星间隔只在同账号、同共享保底池且本地记录完整时显示；否则明确为未知。
- 角色时间线默认/详细模式分别覆盖里程碑和每次获取；武器时间线默认只显示首次，详细模式展开四星/五星每次获取。
- 抽卡派生的角色/武器获取明确提示不覆盖其他获取途径。
- 手工获取覆盖秒、日和周精度、角色原因、可空活动名称、其他原因文本、修订和里程碑重算。
- 相同挑战响应不产生新观察，规范化内容变化产生新观察；一期挑战最多产生一个主时间线完成节点。
- 深境螺旋/剧诗使用最后完成子关卡时间；幽境危战及缺少官方完成时间的记录使用采集时间排序并保持 `OccurredAt` 未知。

## 事务与安全

- 只有确认的新空库允许初始化；未知/未来数据库版本或 application ID 不匹配时停止写入并保留原库，不删表重建。
- 已知旧版通过显式事务迁移；迁移失败不破坏原数据，新 Schema 前完成相关 fixture。
- 业务记录和对应 DataChangeSet 在同一提交边界完成。
- 未来业务记录和 ChangeJournal 必须同事务写入。
- 业务提交后的投影或 UI 刷新失败不删除已经保存的数据。
- 测试使用虚构 UID 和不可用占位凭据；日志断言确保秘密不出现。
- 统计和网络上传默认关闭。
