# 测试要求

状态：Accepted

## 身份与档案

- 同一自然角色可以在两个档案创建不同 `GameAccount.Id`，共享稳定 `GameRoleIdentityId`，记录互不影响。
- 同一档案不能创建第二个相同自然身份副本。
- 导入时源本地 ID 被重映射；稳定身份 GUID 在无冲突时保留。
- 同 GUID 指向不同自然身份时导入失败并报告身份错误。
- 目标已有账号时仍执行完整类别合并和报告。

## 档案名称

- 精确匹配保留首尾空白和大小写差异。
- 模糊名称只产生提示，不自动映射。
- 唯一名称选项默认开启，手工创建和重命名拒绝精确同名。
- 来源内多个同名档案自动编号，编号结果稳定且在预览中可见。
- 已有同名档案时不能开启唯一选项。
- 选项开启后若数据库出现重复，启动被阻塞；修复并重启后恢复。
- 唯一选项关闭且存在多个同名候选时，必须手工映射或新建。

## 导入与修订

- `AddOnly` 不覆盖相同记录；`Upsert` 生成修订并允许撤销。
- 不同类别可以选择不同策略，重复导入幂等。
- 导入中断不留下无法识别的部分状态。
- 普通导入不会因源数据缺失删除目标记录。

## 操作历史

- 撤销按档案计数，默认 3 次。
- 0 表示停止记录新撤销项，1～1000 均有效，1001 被拒绝。
- 跨档案原子 ChangeSet 在各相关档案中各占一次，但只提交和撤销一次。
- 附件和大型 Raw Snapshot 可以支持撤销。
- 空间不足时，不经确认不得清理旧历史；拒绝清理则新操作不提交。
- 清理旧历史不改变当前记录，也不影响尚未确认的 ChangeJournal。

## 不可逆删除

- 删除后具体本地数据和可恢复 Revision 不再存在。
- 保留的 LocalOnlyTombstone 不含具体记录内容。
- 删除不生成远端 Tombstone，不修改导出文件、模拟云备份或其他设备 fixture。
- 自动刷新不静默恢复被抑制数据；显式导入需要警告和确认。

## Portable Dataset 与 Archive

- Schema 验证覆盖必需字段、未知字段和未知枚举。
- 旧版本通过 Migrator 得到当前模型；未知未来 major 被拒绝且数据库不变。
- 哈希错误和截断文件不会改变数据库。
- 大型 NDJSON 流式处理，不要求一次加载全部记录。
- Windows 导出、Android 导入并重新导出后语义一致；反向同样成立。
- 普通 Archive 不包含凭据、DeviceId、平台 URI 或游戏路径。

## 事务与安全

- 业务记录和对应 DataChangeSet 在同一提交边界完成。
- 未来业务记录和 ChangeJournal 必须同事务写入。
- 业务提交后的投影或 UI 刷新失败不删除已经保存的数据。
- 测试使用虚构 UID 和不可用占位凭据；日志断言确保秘密不出现。
- 统计和网络上传默认关闭。
