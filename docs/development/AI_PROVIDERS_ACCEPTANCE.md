# 多个 AI 供应商与模型验收

更新：2026-11-22。基线 `master / 1f9a50c`、工作区起始干净；业务 Schema 12、`0.10.0 / Phase 10.0` 不变。契约见 [ADR 0029](../decisions/0029-multiple-ai-providers-and-models.md)，实际行为见 [AI 架构](../architecture/AI_ANALYSIS.md)。此记录补充先前本地聊天验收，不重新关闭其未运行项。后续三协议和全局配置/工具见 [协议与工具验收](AI_PROTOCOLS_AND_TOOLS_ACCEPTANCE.md)；卡片入口/弹窗与二级页面见 [设置入口验收](AI_SETTINGS_ENTRY_ACCEPTANCE.md)。

## 交付范围

- 设备可以保存多个供应商；供应商有名称、协议、地址和独立安全密钥；每个供应商有多个模型配置，各自保存别名、标识、额度、图片能力和协议参数。
- 设置页新增/编辑/删除，模型可手工填写，或明确获取模型列表后选择填写并保存。填写内容在切换编辑项前需保存。保存设置后的默认选择用于新对话；既有对话保留自己的选择。
- 聊天“切换模型”（Windows）/“模型”（Android）独立选择供应商与模型。切换不发送聊天，旧发送审查失效；实际发送仍显示目的地址、模型、历史和 UID 授权。
- 会话保存本机供应商/模型引用；每轮保留当时供应商名称和模型。旧轮次没有供应商时保持未知，不推断补填。删除配置不删除会话，失效引用阻止发送，直到用户重新选择。
- 旧单供应商文件首次读取迁移为设备 Envelope v2；密钥仍是 WinUI DPAPI / MAUI SecureStorage，按供应商 GUID + 协议 + 规范地址隔离；相同地址也不能串用密钥，改地址不自动携带旧密钥。配置迁移/保存失败恢复原密钥，不覆盖原文件。
- 不改变公开 Portable/Archive，不引入新 AI 框架，不增加原生 Anthropic / Responses、自动模型发现或自动外发资料。

## 复核/真机补测

1. 设置 → AI 卡片 → AI 设置：原有供应商/模型与密钥继续可用；密钥框不回填明文。新增另一个供应商，即使使用相同服务地址，也必须独立填写密钥。
2. 添加至少两个模型，分别设定额度和图片能力后保存；切换编辑项确认不会互相覆盖。获取模型列表不应发送任何聊天/档案；手填模型也可保存。
3. 聊天中切换供应商/模型，审查新目的地址及实际历史，先取消，确认未新增已发送消息；确认发送后每轮显示原服务和模型。单账号不发 UID，整档案逐次授权规则不变。
4. 关闭重开，确认该会话的选择不受另一个会话默认选择变化影响。删除该模型或供应商后仍可查看会话，发送前要求明确重选。
5. Android 真机执行上述步骤，检查选择窗口取消/系统返回不触发请求；图片能力未开启时不得凭空标为支持。
6. 外部服务改为另一个地址/协议后，旧密钥不自动发往新址。不要用真实第三方地址接收测试密钥；此项已有合成请求/安全槽隔离测试。

复核命令沿用 [本地聊天验收](AI_LOCAL_CHAT_ACCEPTANCE.md)，最终全套结果文件为 `src/FurinaChronicle.Tests/TestResults/ai-providers-final.trx`。Android 显式传入 SDK，不将机器路径写入项目文件。完整构建、测试和设备/可见 UI 操作串行。
