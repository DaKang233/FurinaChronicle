# 数据原则

状态：Accepted

1. 数据首先属于用户，用户可以在不依赖 Furina 服务端的情况下导出和迁移数据。
2. 无云服务、无 Furina 账号和离线时，核心档案功能仍应正常工作。
3. 外部通用标准优先于 Furina 自定义格式；支持标准意味着同时实现可靠导入和导出。
4. 公开可移植格式不得依赖 SQLite Schema、MAUI、操作系统路径或平台文件对象。
5. 数据身份不依赖显示名称、头像、图标或本地化文本。
6. 游戏角色身份、档案内数据副本、平台账号和登录凭据具有不同生命周期，必须分离。
7. 同一角色可以存在于多个档案，各档案数据完全独立；共享身份 GUID 应尽量跨设备稳定。
8. 官方响应、标准导入、Furina 导入、本地观察、用户输入和派生结果必须可区分。
9. 事实发生时间、观察时间、抓取时间和导入时间必须可区分。
10. 推断和统计结果不得冒充来源直接提供的事实，并应能由基础记录重新计算。
11. 导入必须幂等，或明确报告冲突、跳过和纠正的原因。
12. 普通导入默认只补充数据，不静默删除现有数据；覆盖和替换必须由用户明确选择。
13. 恢复、导入或刷新失败不得破坏此前已经持久化的数据。
14. 业务记录提交成功后，后续 UI、投影或重新加载失败不得回滚已提交记录。
15. 不完整、未知、推断或不可恢复的信息必须向用户明确说明。
16. 凭据默认不进入普通数据集、全量备份、日志、报告或统计投稿。
17. 已发布格式只能通过版本化迁移演进，不得静默改变既有字段语义。
18. 可选服务端不得成为核心功能的单点依赖。
19. 云备份、设备同步和社区统计是独立能力，必须独立授权。
20. 不可逆删除只影响本地可管理数据；不得暗示它会删除导出文件、其他设备、云备份或统计投稿。
21. 撤销历史按档案计数，可关闭，上限 1000；空间不足导致清理历史前必须获得用户确认。
